    03 / THE ENGINEERING STORY

    Una tienda no es solo
    un carrito bonito.

    La aplicación original usa Next.js, TypeScript y Supabase. El laboratorio público usa el mismo vocabulario de estados, pero no representa una ejecución del backend.

    01 / AUTHORITY

    Precios del servidor.

    El carrito del navegador es una intención. El checkout vuelve a consultar el catálogo y rechaza productos, variantes y cantidades inválidas.

    quoteCheckoutFromCatalog()
    02 / ACCESS

    RLS, no solo login.

    El administrador debe autenticarse y existir en la tabla de administradores; las escrituras se apoyan en políticas de la base de datos.

    Supabase Auth + RLS
    03 / RELIABILITY

    Identidad de pedido.

    Un fingerprint estable del carrito y correo separa reintentos legítimos de solicitudes alteradas. La nueva clave identifica una compra nueva.

    Idempotency-Key
    04 / PAYMENT GATE

    Preparado no es cobrado.

    La integración Mercado Pago está preparada, pero no activa. Una pantalla de éxito nunca sustituye la confirmación servidor a servidor.

    signed webhook + provider read
    REAL CODE / PUBLIC REPOSITORY

    Lo que el recruiter puede comprobar.

    Tests de checkout y precio canónico, carritos obsoletos, autenticación administrativa, export/restore, migraciones SQL, integración de pagos preparada y checklist de producción. El proyecto no se presenta como una tienda de un cliente en producción.
